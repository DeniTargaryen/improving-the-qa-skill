# Блок 3.3 — Unit-тесты слоёв на моках (Track B, закрывает 2.2 на практике)

**Зачем этот блок реально нужен:** прямая цитата из разбора собеса Avito 2026 (`docs/sonnet_reviews/2026-08-12-task-self-review-vs-real-interviews.md`): «...как правильно структурировать такой тест, ...как мокать внешние зависимости (например, платёжный шлюз)». Это ровно тот сценарий: слой (`posts_layer.py`/`shape_checks.py`) тестируется **без единого HTTP-запроса**, через `unittest.mock`, — то, что в 2.2 было «зачем нахуй» на изолированной игрушечной функции, здесь применяется к реальному слою API-клиента.

Самодостаточно: `mocked_api.py`/`posts_layer.py`/`shape_checks.py` в этой папке — **готовые**, не переписывай их. Твоя работа — только тесты.

```bash
python -m pytest 03_api_framework/3.3_unit_tests_with_mocks -v
```

## Файлы

| Файл | Кто пишет | Что внутри |
|------|-----------|------------|
| `mocked_api.py` | готово, **не трогай** | клиент (тот же, что в 0.4) |
| `posts_layer.py` | готово, **не трогай** | `get_post`/`get_posts` |
| `shape_checks.py` | готово, **не трогай** | сильная версия `check_post_shape` (как в 2.3) |

## Какая проблема

`get_post`/`get_posts` дёргают реальную сеть (через `posts_client` внутри `posts_layer.py`). `check_post_shape` не дёргает сеть вообще, ей просто дают `dict`. Задача — написать unit-тесты и на то, и на другое, но **без единого реального HTTP-запроса** за весь прогон этого файла.

## Фича — две части теста (без разделения на «А/Б» файлами, просто два разных вида проверки в одном файле)

### 1. `check_post_shape` — совсем без моков (это уже unit-тест по определению)

Собери руками несколько `dict` (валидных и невалидных, можешь взять идею кейсов из `02_pytest_craft/2.3_strong_asserts`, не копируй файл) и прогони через `check_post_shape`. Никакого мока не нужно — функция и так не лезет в сеть.

### 2. `get_post`/`get_posts` — через `unittest.mock.patch`

Замокай `posts_layer.posts_client.get` (или `BaseApi.get` — выбери, как удобнее; оба варианта валидны, главное — реальный `requests` не должен сработать).

## Кто кого вызывает

```python
with patch("posts_layer.posts_client.get") as mock_get:
    mock_get.return_value = {"id": 1, "userId": 1, "title": "T", "body": "B"}
    result = get_post(post_id=1)
    assert result == {"id": 1, "userId": 1, "title": "T", "body": "B"}
    mock_get.assert_called_once_with(path="/posts/1")
```

1. Тест подменяет `posts_client.get` на мок.
2. Тест вызывает `get_post(post_id=1)` как обычную функцию (не трогает мок напрямую).
3. Внутри `get_post` вызывается `posts_client.get(path="/posts/1")` — но это уже подмена, не реальный HTTP.
4. Тест проверяет: а) `get_post` вернула ровно то, что отдал мок, б) мок был вызван с правильным `path`.

### Что возвращает (проверка, не функция)

| Функция под тестом | Что мокаем | Что проверяем |
|---------------------|------------|-----------------|
| `check_post_shape(dict)` | ничего (не нужно) | падает/не падает на валидных/невалидных dict |
| `get_post(post_id)` | `posts_client.get` | вернула то, что отдал мок; мок вызван с `path=f"/posts/{post_id}"` |
| `get_posts()` | `posts_client.get` | вернула то, что отдал мок (список постов); мок вызван с `path="/posts/"` |

**Минимум:** по одному тесту на `check_post_shape` (валидный + невалидный кейс — можно объединить или разделить), один на `get_post`, один на `get_posts`. Итого 3–4 теста в файле, без сети вообще.
