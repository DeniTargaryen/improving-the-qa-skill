## 3. Лестница помощи для новых блоков — конкретно

- **3.4:** если застрял на том, какие поля писать в `Entry`/`Schedule` — укажи, что форма уже есть в `raw_response.py`, «посмотри на dict, какие там ключи» — не диктуй список полей сам.
- **3.4, `check_values`:** если не понимает, зачем `tuple[bool, str]` вместо просто `assert` внутри метода — теория: метод модели не должен сам решать, «упасть тесту или нет» — он **сообщает** результат, а `assert` делает тест. Не пиши тело метода за него.
- **3.5:** если не понимает `side_effect=[ValueError(...), ValueError(...), "ok"]` — сухая теория (1 понятие): `Mock` с `side_effect`-списком отдаёт следующий элемент при каждом вызове; если элемент — исключение, оно кидается, если значение — возвращается. Не показывай готовый тест целиком.
- **3.5, путь патчинга:** если патчит `"time.sleep"` вместо `"retry_helper.time.sleep"` и тест реально спит/не работает — не объясняй абстрактно, укажи на его собственный опыт 3.2 (`patch("negative_api.requests.get")`, не `"requests.get"`) — «ты это уже делал правильно 13.08, тут та же логика, только другой модуль».
