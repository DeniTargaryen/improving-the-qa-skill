### 2. «Раздели все эти типы на две группы — какая разница»

Не ответил на месте. Потом загуглил: **изменяемые / неизменяемые**. Сам говорит: **не знает, кто куда относится и что это значит**. Это пробел, не «забыл слово».

**В план (обязательно, до следующих скринингов):**

| Неизменяемые (immutable) | Изменяемые (mutable) |
|--------------------------|----------------------|
| `int`, `float`, `bool`, `str`, `tuple`, `frozenset`, `bytes`, `None` | `list`, `dict`, `set` |

Разница своими словами для собеса: неизменяемый объект после создания не меняется «на месте» (операции дают **новый** объект); изменяемый можно менять через методы (`append`, `d[k]=v`) — тот же объект в памяти. Связь с уже сданным 1.4: ловушка `def f(x=[])` именно потому что **list mutable**; `is` vs `==` — про объект в памяти.

`Decimal` — из модуля `decimal`, не builtins; на скрининге можно сказать «из стандартной библиотеки, для денег, неизменяемый».

### 3. Аннотации типов у функции (аргументы или возврат?)

Вопрос был странный / не расслышал: ожидаемый тип **аргументов** или **того, что вернёт**.

Его ответ: если в аргументах указано `str`, IDE при вызове будет ругаться на неверный тип.

**Где косяк (коуч):** аннотации в Python **по умолчанию не проверяются в рантайме**. Это подсказки для людей, IDE и отдельных инструментов (`mypy`, `pyright`). Без них программа **запустится** с `int` вместо `str`.  
Два места в сигнатуре:

```python
def f(name: str) -> dict:
    ...
```

- `name: str` — ожидаемый тип **аргумента**
- `-> dict` — ожидаемый тип **возврата**

IDE может подсветить, интерпретатор — нет (пока не подключили проверщик).
