# А) Зарегистрировать маркер `regression` — правишь корневой `pytest.ini`

## Какая проблема

Открой `test_markers_demo.py` — там уже стоит `@pytest.mark.regression` на двух тестах. Если прямо сейчас прогнать `python -m pytest 02_pytest_craft/2.4_markers_and_config -v`, pytest покажет предупреждение `PytestUnknownMarkWarning` — маркер используется, но **не зарегистрирован**.

## Фича

В корневом `pytest.ini` (не создавай новый файл — используй тот, что уже есть в корне репозитория) в секции `markers` добавь строку под `regression` по аналогии с уже существующим `smoke`:

```ini
markers =
    smoke: быстрый критичный сценарий
    regression: полный regression-сценарий, не для каждого прогона
```

## Кто кого вызывает

1. pytest при старте читает `pytest.ini` из корня репозитория (там, где `testpaths`).
2. Секция `markers` — это список маркеров, которые pytest считает «официальными» (не предупреждает про них).
3. После твоей правки предупреждение `PytestUnknownMarkWarning` на `regression` должно пропасть.

### Что возвращает (проверка, не функция)

| Команда | Ожидание до правки | Ожидание после правки |
|---------|---------------------|--------------------------|
| `pytest ... -v` (весь блок) | Warning про `regression` | Без warning |
| `pytest ... -m smoke -v` | 2 теста (уже помечены, `smoke` уже зарегистрирован) | То же |
| `pytest ... -m regression -v` | 2 теста + warning | 2 теста, без warning |
| `pytest ... -k "checkout" -v` | 1 тест (`test_full_checkout_regression` — совпадение по имени функции, не по маркеру) | То же |

**Разница `-m` и `-k` из этого примера:** `-m regression` фильтрует **по маркеру** (не важно, как называется функция), `-k "checkout"` фильтрует **по подстроке в имени теста** (не важно, есть ли маркер). Это и есть материал для устного ответа №4 в части Б.
