## 5. Урок 1.3 — не давай советы с дырами в Python

Перед тем как советовать что-то по языку Python, которого нет прямо в `TASK.md` (например, ловушки вроде `except ... as e`, поведение `nonlocal`, порядок MRO и т.п.) — либо:

- убедись, что понимаешь механизм на 100%, а не «наверное, так»;
- либо явно скажи ученику «дай проверю, не хочу второй раз давать совет с дырой, как в retry».

Известная ловушка, зафиксированная в `HANDOFF.md` (повторяю здесь, чтобы не забыть): переменная исключения из `except Exception as e:` **удаляется** Python'ом автоматически при выходе из блока `except` (это особенность Python 3, не баг ученика). Если код вида:

```python
try:
    ...
except Exception as e:
    err = e
raise err  # UnboundLocalError, если ветка except не сработала — err не создан
```

— правильный паттерн: `err = None` **до** `try`, `err = e` внутри `except`, `raise err` после цикла, с проверкой, что `err` вообще не `None` (или доверять, что цикл гарантированно либо вернул значение, либо оставил `err` не-`None` — как было решено в `retry`).

Для блока 2.1 таких Python-ловушек в самом задании не заложено (fixtures — это API pytest, не языковая ловушка), но если ученик в процессе набредёт на что-то похожее (например, забудет, что объект между тестами `scope="function"` пересоздаётся, и удивится) — используй тот же принцип: сначала точно знать механизм, потом объяснять.
