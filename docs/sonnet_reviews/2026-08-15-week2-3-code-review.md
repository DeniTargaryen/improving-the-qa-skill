## 1. Блок 3.1 — CRUD (`crud_api.py`, `test_crud.py`)

**Прочитано целиком.**

Что усвоено реально: `post`/`put`/`patch`/`delete` написаны ученик**ом** самим, по образцу `get` — структура «собрать URL → `requests.<method>` → `assert` статуса → `return`» воспроизведена во всех четырёх методах без ошибок. Что коуч правил (честно записано в шапке файлов, не спрятано):

На собесе стоит уметь произнести именно эту фразу («jsonplaceholder — фейковый бэкенд, не хранит данные по-настоящему, поэтому для проверки update/delete нужно бить по существующему ID, не по только что созданному»), а не стыдиться, что «тест пришлось подправить».

## 2. Блок 3.2 — исключения + негатив (`negative_api.py`, `api_errors.py`, `test_exceptions_negative.py`)

**Прочитано целиком.**

`ApiError(Exception)` / `NotFoundError(ApiError)` — написаны сам, иерархия верная (это повтор 1.2, но теперь классы реально **используются** клиентом, не лежат «ярлыком в вакууме» — закрывает старую претензию ученика по 1.2, см. `STUDENT_FEEDBACK_for_sonnet.md`).

`get()` в `negative_api.py` — рефакторинг с `assert` на `raise` сделан верно: 404 → `NotFoundError`, любой другой не-200 → `ApiError`. Ветвление `if/if/else` работает, хотя третий `if` технически избыточен (после первого `if` с `return` внутри не потребовался бы `else`) — это стилистическая мелочь, не ошибка логики, **не поднимать на ревью как проблему**, это не тема блока.

`test_exceptions_negative.py`: живой 404 (`pytest.raises(NotFoundError)`) — ок. Кейс 500 через `patch("negative_api.requests.get")` — рабочий, `mock_get.return_value.status_code = 500` правильно эмулирует объект `Response` без реального запроса. Мелкая лишняя строка (внутри `with patch` повторно создаётся `api = BaseApi(...)` — не нужно, старый `api` снаружи уже валиден) — **не влияет на смысл теста**, не тема для повторного ревью.

**Дороже всего здесь — не код, а стоимость получения кода:** по записи в шапке файла и по `STUDENT_FEEDBACK_for_sonnet.md`, ~30 минут ушло на понимание `patch` из-за того, что коуч сначала объяснял жаргоном («клиент», «сеть») и показал готовый `with patch(...)` без импорта и без построчного разбора. Это правило уже зафиксировано в `.cursor/rules/interview-prep-coach.mdc` §0 — в этом пакете не повторяю нотацию, просто подтверждаю: инцидент был, урок учтён, коучу напоминание — в `COACH_RECS_2026-08-15.md`.

**Вывод:** 3.2 усвоено руками. Патч-механику ученик реально прогнал через боль один раз — усвоение неглубокое (по признанию самого ученика 15.08: «сегодня уже слабо помню, что писал 13.08»), поэтому нужен **не переспрос старого файла**, а свежий вход на новую зависимость. Это и есть материал для нового блока 3.5 ниже.

## 5. Неделя 1 (`01_python_core`) — по `STUDENT_FEEDBACK_for_sonnet.md`

Не переоткрывал код (нет активной претензии к коду, только к формату заданий, уже разобранному в ревью 10.08/12.08). Зафиксированные незакрытые устные дырки недели 1, подтверждённые `CALENDAR.md` («Долги»):
