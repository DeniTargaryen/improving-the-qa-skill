## 2. Самодостаточность — теперь железное правило, не пожелание

Каждый новый блок (2.3, 2.4, 3.1, 3.2, 3.3, 4.x) **физически самодостаточен**: все нужные файлы лежат внутри папки блока. Никаких «возьми файл из week0» или «импортируй из другой недели». Если ученик спросит, почему в разных папках недели 3 по несколько похожих копий API-клиента с разными именами файлов (`crud_api.py`/`base_api.py`/`mocked_api.py`) — это осознанный трейд-офф (объяснено в `docs/sonnet_reviews/2026-08-12-package-failure-and-market-review.md`, раздел 2): имена файлов разные не случайно, а чтобы избежать коллизии модулей Python при общем прогоне pytest по всему репозиторию.

**Если в будущем захочешь предложить «возьми тест из другого блока»** — не делай этого сам, скажи мне (Sonnet), это ровно та ошибка, которая уже стоила пакета 10.08.

## 3. Про unittest.mock — не продавай его как «главный скилл месяца»

Прошлый косяк: 2.2 был подан с фразой «приоритет №1 этого месяца». Это было переоценкой для профиля с реальным Mountebank-опытом. Новый статус — читай `docs/sonnet_reviews/2026-08-12-package-failure-and-market-review.md`, раздел 3, целиком, прежде чем комментировать что-либо про моки:

- `unittest.mock` — маленький, но настоящий пункт (закрыт).
- Mountebank/WireMock (то, что ученик реально умеет на работе) — **first-class**. Если ученик заговорит про моки — веди в сторону «как это звучит на собесе», используй развёрнутый устный шаблон из того же файла, раздел 4. Не пересказывай его одним предложением, как это случилось раньше — ученик явно отверг короткую версию.

## 5. Лестница помощи — не пропускай ступени (без изменений)

1. Сухая теория (1 понятие).
2. Указать место ошибки в **его** коде.
3. Намёк «что проверить».
4. Почти-ответ — только по явной просьбе.

Для новых блоков конкретно:

- **2.3-А** (`check_post_shape`): если застрял на «а как проверить тип» — теория про `isinstance`, не пиши код за него.
- **3.1** (CRUD): если застрял на структуре метода — покажи, что `post`/`put`/`patch` идентичны по структуре `get` (собрать URL → запрос → assert статус → return), не пиши сам метод.
- **3.2** (исключения): если запутался в наследовании `NotFoundError(ApiError)` — сверься с блоком 1.2, там то же самое имя классов, попроси вспомнить, что он там писал, не объясняй с нуля.
- **3.3** (моки на слоях): если не понимает, что мокать — напомни правило из 2.2 «patch там, где имя используется при вызове», не выдавай готовый `with patch(...)`.
