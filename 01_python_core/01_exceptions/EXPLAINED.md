# Исключения без магии — шпаргалка к 1.2

## Главный отвал мозга: «что ДЕЛАЕТ этот класс?»

**Ничего.** В теле `ApiError` / `NotFoundError` **нет** действий.

Это не `Account`. У Account есть «положить деньги», «снять».  
У ошибки **нет** «посчитать», «вернуть строку», «описать себя».

Единственная работа класса ошибки в этом задании:

> **иметь имя** и **стоять в цепочке наследования**, чтобы Python и тесты могли сказать:  
> «это ApiError» / «это NotFoundError» / «NotFoundError — тоже ApiError».

Наследование **уже и есть** вся работа части А.  
Тело класса — пустое: `pass` или `...`. Точка.

---

## Тогда зачем наследовать Exception, если я его не вижу?

`Exception` — встроенный класс Python. Его код в стандартной библиотеке, ты его **не открываешь** и **не копируешь**.

Что внутри родителя тебе **не нужно знать построчно**. Важно только:

| Уже умеет `Exception` | Значит твой `ApiError` умеет то же «бесплатно» |
|------------------------|--------------------------------------------------|
| его можно `raise` | `raise ApiError("текст")` работает |
| у ошибки есть текст сообщения | `"текст"` попадает в ошибку |
| его можно ловить | `except ApiError` / `pytest.raises(ApiError)` |
| можно проверить родство | `issubclass(NotFoundError, ApiError)` |

Ты **не пишешь** эти умения сам. Ты только говоришь: «мой ярлык — ребёнок Exception / ApiError».

Аналогия: ты заводишь новый **ярлык на полке** «NotFound».  
Полка уже умеет держать банки. Ярлык сам банки не крутит.

## Что конкретно должен делать `ApiError`?

| Вопрос | Ответ |
|--------|--------|
| Какие методы писать? | **Никаких** |
| Что `return`? | **Ничего** (в классе ошибок `return` вообще не пишут) |
| Что хранить в полях? | **Ничего** в этом задании |
| Что написать в теле? | `pass` или `...` |
| Зачем класс тогда? | Чтобы тесты/код могли отличить «API-ошибка» от `ValueError` / `ZeroDivisionError` |

То же для `NotFoundError`, плюс: он **ребёнок** `ApiError`, чтобы ловить «любую API-ошибку» через родителя (это как раз проверяет тест `test_catch_as_api_error`).

---

## Где тогда «действие»?

Не внутри класса. Снаружи:

1. Кто-то пишет `raise NotFoundError("missing")` → Python создаёт объект ошибки этого типа и прерывает код.  
2. Кто-то ловит `pytest.raises(NotFoundError)` / `except ApiError`.

В части А **raise пишет тест**, не ты.  
Ты только объявил имя типа.

В части Б действие в **функции** `safe_divide`: там уже `raise ZeroDivisionError` при нуле.

## Что у тебя сейчас не то

В `exceptions.py` написано что-то вроде «положить строку в `s` и `return s`».

Так **не работает** класс ошибки:

- тело класса — не функция; `return` там бессмысленен для задания;
- класс не обязан «вернуть описание»;
- тесту не нужна твоя строка — ему нужно, чтобы **существовали типы** `ApiError` и `NotFoundError` с правильными родителями.

Убери из тел всё лишнее. Оставь объявление класса + пустое тело.

## return vs raise (часть Б — функция)

| | |
|--|--|
| `return 5` | успех, наружу число |
| `raise ZeroDivisionError("...")` | авария, наружу ошибка |

`safe_divide` — обычная **функция**. Raise — там, не в `ApiError`.
