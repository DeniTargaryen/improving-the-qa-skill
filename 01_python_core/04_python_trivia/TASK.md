# А) `is` vs `==` — только `ANSWERS.md`

## Какая проблема

На собесе часто спрашивают: чем `a is b` отличается от `a == b`, и когда `is` врёт ожиданиям.

Простыми словами:

- `==` — «значения похожи?» (сравнивает содержимое, как ты обычно думаешь).
- `is` — «это **один и тот же объект** в памяти?» (не «похожи», а «тот же самый»).

## Что сделать

В `ANSWERS.md` ответь своими словами (2–5 предложений на пункт):

1. Чем `is` отличается от `==`.
2. Почему `a = [1, 2]; b = [1, 2]; a == b` обычно True, а `a is b` — False.
3. Почему для `None` на работе пишут `if x is None`, а не `if x == None`.

Тестов на А нет — коуч читает `ANSWERS.md`.

# Б) Ловушка «список в параметрах по умолчанию» — `trivia.py`

## Какая проблема

В AQA иногда делают хелпер «положи элемент в список»:

```python
def add_item(item, bag=[]):
    bag.append(item)
    return bag
```

Кажется: «если `bag` не передали — возьми пустой список».  
На деле один и тот же список-по-умолчанию **живёт между вызовами**. Второй вызов без `bag` видит мусор от первого.

## Фича

Написать `add_item` **без** этой ловушки.

## Кто кого вызывает

Тест вызывает твою функцию напрямую:

```python
add_item("a")
add_item("b")
```

Ты не пишешь тест. Ты чинишь функцию в `trivia.py`.

### Что возвращает

- тип: `list`
- смысл: список, в конец которого добавлен `item`
- если `bag` передали — меняешь **этот** список и возвращаешь его же
- если `bag` не передали — новый список только для этого вызова

| Вызов | Ожидание |
|-------|----------|
| `add_item("a")` потом отдельно `add_item("b")` | второй вызов вернул `["b"]`, **не** `["a", "b"]` |
| `bag = []; add_item("x", bag); add_item("y", bag)` | `bag == ["x", "y"]` |

Подсказок по синтаксису в чате можно просить; в TASK: обычный приём — по умолчанию `None`, внутри создать новый `list`, если не передали.

# В) Поверхностная vs глубокая копия — `ANSWERS.md` + чуть кода

## Какая проблема

Есть список списков (как «таблица»):

```python
rows = [[1, 2], [3, 4]]
```

Сделали «копию» через `.copy()` (или `list(rows)`). Поменяли `copy[0][0] = 99`.  
Удивление: в **исходном** `rows` тоже стало 99.

Потому что `.copy()` копирует **верхний** список, а внутренние списки — те же объекты.

## Что сделать

1. В `ANSWERS.md` своими словами: чем `.copy()` отличается от `copy.deepcopy(...)` на таком примере.
2. В `trivia.py` допиши функцию `clone_rows(rows)`:

### Что возвращает `clone_rows`

- тип: `list` (список списков)
- смысл: копия, где изменение внутреннего элемента **не** портит исходный `rows`
- пустой вход: вернуть пустой список `[]`

| Вход | Действие после вызова | Ожидание |
|------|------------------------|----------|
| `rows = [[1], [2]]`, `c = clone_rows(rows)`, потом `c[0][0] = 9` | `rows[0][0]` | всё ещё `1` |
| `rows = []` | `clone_rows(rows)` | `[]` |

Можно использовать модуль `copy` из стандартной библиотеки.

# Г) Прокинуть аргументы дальше — `trivia.py`

## Какая проблема

В декораторах / обёртках API часто нужно вызвать чужую функцию **с теми же** позиционными и именованными аргументами, что пришли к тебе.  
Ты это уже трогал в `timeit` / `retry` (`*args`, `**kwargs`). Здесь — отдельно и явно.

## Фича

Функция `call_with(fn, *args, **kwargs)`:

- вызывает `fn` с переданными args/kwargs;
- возвращает **то же**, что вернула `fn`;
- если `fn` упала — ошибка уходит наружу (не глотать).

### Что возвращает

| Вызов | Ожидание |
|-------|----------|
| `call_with(add, 2, 3)` где `add` складывает | `5` |
| `call_with(greet, name="Ann")` где greet → `"hi Ann"` | `"hi Ann"` |
| `call_with(boom)` где boom делает `raise ValueError` | наружу `ValueError` |
