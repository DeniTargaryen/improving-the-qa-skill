# Блок 1.2 — Ошибки (исключения). Объяснение для человека, который классы только начал

Забудь слово «рэйсят» на минуту. Ниже — что делать руками.

## Две разные вещи в этом блоке

### А) Придумать **имена типов ошибок** (`exceptions.py`)

Это почти пустые классы. Они **ничего не считают**.  
Они только говорят: «бывает ошибка типа ApiError» и «бывает ошибка типа NotFoundError».

Как `ValueError` уже есть в Python — ты делаешь свои названия.

### Б) Написать **функцию** `safe_divide` (`safe_divide.py`)

Обычная функция (не класс Account).  
Делит числа. Если делить на ноль нельзя — **прерывает работу с ошибкой**.

Тесты проверяют и А, и Б.

---

## Часть А — `exceptions.py` по шагам

Нужно ровно это (смысл):

1. Класс с именем `ApiError`, родитель — встроенный `Exception`.  
2. Класс с именем `NotFoundError`, родитель — твой `ApiError`.

Тело можно `pass` (пусто: «класс есть, своего кода нет»).

**Где тут raise?** Нигде в этих классах.  
Классы ошибок сами по себе не «стреляют». Они как ярлыки.

**Кто тогда делает raise?**  
- либо **твоя функция** (часть Б), когда случилась плохая ситуация;  
- либо **тест** специально пишет `raise NotFoundError("...")`, чтобы проверить, что такой ярлык можно поймать.

Тест уже написан. Тебе в `exceptions.py` нужно только **объявить** два класса. Тест сам сделает `raise` и `pytest.raises`.

## Часть Б — `safe_divide(a, b)` по шагам

Это **функция**, как `normalize_phone` или `two_sum_dict`. Не метод Account.

### Что должна делать

| Вызов | Что должно произойти |
|-------|----------------------|
| `safe_divide(10, 2)` | **вернуть** число `5` (результат 10/2) |
| `safe_divide(1, 0)` | **не вернуть число**, а оборвать работу ошибкой `ZeroDivisionError` |

### Что значит «оборвать ошибкой»

Вместо `return 5` пишешь roughly:

```text
raise ZeroDivisionError("какой-то текст")
```

`raise` = «стоп, случилась ошибка такого типа».  
Это не return. Наружу уходит исключение, тест ловит его через `pytest.raises(ZeroDivisionError)`.

### Где писать raise?

**Внутри функции `safe_divide`**, когда `b` равен нулю.  
Не в классе ApiError. Не обязательно в тесте (тест уже ждёт ошибку).

Логика словами:

1. если делитель 0 → `raise ZeroDivisionError`  
2. иначе → `return a / b`
