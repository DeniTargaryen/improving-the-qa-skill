# А) `timeit` — файл `timeit_deco.py`

## Какая проблема

Есть обычная функция, например сложение. Тебе иногда нужно **узнать, сколько она шла по времени**, но результат функции должен остаться тем же (`2+3` по-прежнему `5`).

Без этого упражнения каждый раз пришлось бы руками писать «засеки время → вызови → напечатай → верни» вокруг каждой функции.  
Фича: один раз написал `timeit`, потом над функцией ставишь `@timeit` — и замер появляется сам.

## Кто кого вызывает (на примере из теста)

В тесте roughly так:

```python
@timeit
def add(a, b):
    return a + b

add(2, 3)  # должно дать 5, и что-то напечатать в консоль
```

Что делает Python из-за `@timeit`:

1. Берёт твою функцию `add`.
2. Передаёт её в **твой** `timeit(...)`.
3. То, что `timeit` **вернул**, становится новым `add`.
4. Когда тест пишет `add(2, 3)`, вызывается уже **то, что вернул `timeit`**, а не голый `def add` напрямую.

Значит `timeit` должен:

- принять функцию (в тесте это `add`);
- **вернуть другую функцию**;
- эта другая функция при вызове: засекает время → вызывает исходный `add` → печатает время (`print`) → **возвращает то же**, что вернул `add` (для `add(2,3)` это `5`).

Если исходная функция упала с ошибкой — ошибка должна уйти наружу, не глотать.

### Что возвращает

| Вызов | Наружу |
|-------|--------|
| `add(2, 3)` под `@timeit` | `5` |
| функция вернула dict | тот же dict |
| функция сделала `raise` | тот же `raise` |

# Б) `Timer` — файл `timer.py`

## Какая проблема

Нужно замерить **кусок кода** (не одну функцию), как секундомер. В тесте это выглядит так:

```python
with Timer() as t:
    time.sleep(0.05)
# здесь у t должно быть число секунд, сколько шёл блок
t.elapsed
```

## Что такое `with` здесь (если на работе не юзал)

`with ... as t:` — специальная конструкция Python. Ты **не обязан** был знать её с работы.

Смысл для этого задания:

1. Перед блоком Python создаёт объект (`Timer()`).
2. Вызывает у него `__enter__` — «старт» (у нас: запомнить время начала; вернуть объект в `t`).
3. Выполняет код внутри отступа (sleep и т.д.).
4. Потом вызывает `__exit__` — «финиш» (у нас: записать, сколько секунд прошло, в `t.elapsed`).

Тебе нужно только реализовать эти два метода у класса `Timer`. Остальное делает сам `with`.

## Кто кого вызывает

1. Создаётся `Timer()`.
2. При входе в `with` Python вызывает у него метод `__enter__`.
3. То, что `__enter__` **вернул**, попадает в переменную `t` (в тесте нужно вернуть **сам этот Timer**, то есть `self`).
4. Выполняется тело (`sleep` и т.д.).
5. При выходе Python вызывает `__exit__` — тут записываешь в `self.elapsed`, сколько прошло секунд.

### Что должно получиться

| Момент | Ожидание |
|--------|----------|
| `with Timer() as t` | `t` — этот же объект Timer |
| после `with` | `t.elapsed` — число `float` ≥ 0 |
| внутри был sleep ~0.05с | `elapsed` не меньше примерно 0.04 |

# В) `retry` — файл `retry.py`

## Какие файлы и кто что пишет (чтобы не путаться)

| Файл | Кто пишет | Что внутри |
|------|-----------|------------|
| `test_decorators.py` | уже готово, **не трогай** | функции `flaky` / `always_fail` / `stable` + проверки |
| `retry.py` | **ты** | только общая логика повторов |

Тест **не** лежит внутри `retry.py`. Тест импортирует твой `retry` и сам вешает `@retry(times=...)` на свои функции.  
Ты **не** копируешь `flaky` к себе. Ты пишешь механизм, который умеет вызывать **любую** переданную функцию несколько раз.

**Времени / `sleep` тут нет.** Это не `timeit`.  
`times=3` = максимум **3 вызова** функции, не 3 секунды.

## Какая проблема

`flaky` в тесте:

- 1-й вызов → ошибка;
- 2-й вызов → ошибка;
- 3-й вызов → вернула `"ok"`.

Нужно: при ошибке попробовать ещё, пока не кончится лимит `times`.  
Успех = функция **вернула** значение → отдай **это же** значение (`"ok"`, `10`, …).  
Все попытки с ошибкой → наружу уходит **та же** ошибка (не новая `Exception("что-то")`).

## Почему у `retry` в скобках только `times`, а `flaky` всё равно доступна

Сравни с упражнением А, которое ты уже сдал.

**`@timeit`** (без скобок) — Python делает один шаг:

```text
add = timeit(add)
```

Поэтому у тебя было `def timeit(fn):` — функция приходит сразу аргументом.

**`@retry(times=3)`** (со скобками) — Python делает **два** шага:

```text
шаг 1:  tmp = retry(3)       # в retry попало только число 3
шаг 2:  flaky = tmp(flaky)   # flaky передали уже в то, что вернул retry(3)
```

Потом тест пишет `flaky()` — вызывается **то, что вернул шаг 2**.

Значит в `retry.py` нужны **три** функции одна в другой:

```text
def retry(times=3):           # этаж 1: получил число
    def middle(fn):           # этаж 2: получил flaky (один аргумент — функция)
        def inner(*args, **kwargs):   # этаж 3: это вызывают как flaky()
            # тут цикл попыток; внутри вызываешь fn(...)
            ...
        return inner          # middle отдаёт inner
    return middle             # retry(3) отдаёт middle
```

### Важно про аргументы (частая ошибка)

| Этаж | Что в скобках `def` | Откуда берётся `times` / `fn` |
|------|---------------------|-------------------------------|
| `retry` | только `times` | с декоратора `@retry(times=3)` |
| `middle` | только `fn` | Python на шаге 2 передал `flaky` |
| `inner` | обычно `*args, **kwargs` (как в `timeit`) | тест вызвал `flaky()` |

**Не пиши** `def middle(fn, times)` и **не пиши** `def inner(fn, times)`.  
`times` уже есть с этажа 1 — внутри вложенных функций его можно **читать**, второй раз в параметры класть не надо.  
`fn` уже есть с этажа 2 — на этаже 3 его вызывают (`fn(...)`), снова принимать параметром не надо.

## Что делает этаж 3 (цикл)

До `times` раз:

1. Вызови `fn(...)`.
2. Если **не упала** — `return` её результат (для первого теста это `"ok"`).
3. Если **упала** — не сдавайся сразу: следующая попытка (пока лимит не кончился).
4. Если все попытки упали — `raise` **ту же** ошибку, что была (тест ждёт `ValueError` / `ConnectionError`, не твою новую `Exception`).

Запрещено: `except: raise Exception` — это и повторы ломает, и подменяет тип ошибки.

## Три проверки из теста

| Функция в тесте | times | Наружу |
|-----------------|-------|--------|
| `flaky` (2 раза падает, потом `"ok"`) | 3 | `"ok"`, внутри 3 вызова |
| `always_fail` (всегда `ValueError`) | 2 | `ValueError`, внутри 2 вызова |
| `stable` (сразу `return 10`) | 5 | `10`, внутри **1** вызов |

## С чего начать

1. Сотри из `retry.py` `sleep`, копипасту `flaky` из теста, возврат чисел.
2. Собери три этажа и два `return`, как таблица выше (имена `middle`/`inner` можно свои).
3. Потом наполни цикл на этаже 3.
