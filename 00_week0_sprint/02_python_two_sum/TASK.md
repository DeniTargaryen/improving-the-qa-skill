## Зачем

Классика лайвкодинга / скрининга. Показывают, умеешь ли ты:
1. перебрать все пары (brute force);
2. ускорить через словарь (O(n)).

На собесе часто просят **оба** варианта и спросить про сложность.

## Условие

Дан список чисел `nums` и число `target`.  
Найди **два разных индекса** `i` и `j` (`i < j` не обязательно в ответе, но индексы разные), такие что:

`nums[i] + nums[j] == target`

Верни кортеж/список из двух индексов.  
Если пары нет — верни `None`.

Гарантии для наших тестов:
- числа могут повторяться;
- если решений несколько — подойдёт **любое** корректное;
- один и тот же элемент дважды использовать нельзя (разные индексы).

Пример: `nums = [2, 7, 11, 15]`, `target = 9` → `(0, 1)` потому что `2 + 7 = 9`.

## Что реализовать

В `solution.py` две функции:

### 1. `two_sum_brute(nums: list[int], target: int) -> tuple[int, int] | None`

Два вложенных цикла. Без словаря.  
Сложность по времени примерно O(n²) — это ок для этой функции.

### 2. `two_sum_dict(nums: list[int], target: int) -> tuple[int, int] | None`

Один проход + словарь «значение → индекс».  
Идея: для текущего числа `x` смотри, есть ли уже в словаре `target - x`.  
Если есть — нашли пару. Если нет — запомни `x` и его индекс.
