## Какая проблема

`get` в `crud_api.py` уже умеет прочитать данные. Но реальный API-клиент на работе должен уметь **создавать**, **менять** и **удалять** — иначе на живом собесе, когда попросят «дополни клиент методом создания сущности», будет пусто.

## Фича

Четыре метода в `BaseApi`, по образцу уже готового `get`:

- `post(self, path, json, expected_status=201) -> dict` — создать.
- `put(self, path, json, expected_status=200) -> dict` — заменить целиком.
- `patch(self, path, json, expected_status=200) -> dict` — частично обновить.
- `delete(self, path, expected_status=200) -> None` — удалить.

## Кто кого вызывает

Тест (который пишешь ты) создаёт клиент и вызывает методы по очереди, как реальный сценарий CRUD:

```python
api = BaseApi("https://jsonplaceholder.typicode.com")
created = api.post("/posts", json={"title": "x", "body": "y", "userId": 1})
updated = api.put(f"/posts/{created['id']}", json={"title": "новый", "body": "y", "userId": 1})
api.delete(f"/posts/{created['id']}")
```

Внутри каждого метода — та же схема, что в `get`: собрать полный URL (`self.base_url + path`), сделать запрос через `requests`, проверить статус через `assert` (как в `get`), вернуть `r.json()` (для `delete` — вернуть `None`, тело ответа не важно).

`jsonplaceholder` не хранит данные по-настоящему (после `post` он всегда отвечает похоже, `id` часто `101`), но честно валидирует форму запроса и код ответа — этого достаточно для тренировки контракта.

### Что возвращает каждый метод

| Метод | Тип возврата | Смысл | Ошибка/пустой вход |
|-------|--------------|-------|----------------------|
| `post` | `dict` | тело созданной сущности (обычно с `id`) | если статус не совпал с `expected_status` — `AssertionError` (как в `get`) |
| `put` | `dict` | тело обновлённой сущности | то же |
| `patch` | `dict` | тело обновлённой сущности | то же |
| `delete` | `None` | ничего, только проверка статуса | то же |

| Вызов | Ожидание |
|-------|----------|
| `api.post("/posts", json={...})` | статус `201`, вернул `dict` с новым `id` |
| `api.put(f"/posts/{id}", json={...})` | статус `200`, вернул `dict` |
| `api.patch(f"/posts/{id}", json={"title": "только заголовок"})` | статус `200`, вернул `dict` |
| `api.delete(f"/posts/{id}")` | статус `200`, вернул `None` |

## Что писать в тестах

Минимум: по одному тесту на каждый метод (4 теста) **или** один сквозной тест «создать → обновить → удалить», если тебе так понятнее — оба варианта нормальные, выбирай сам.
