## Что сделать

В `test_normalize_phone.py` напиши тесты так, чтобы были **все** пункты:

### 1. Обычный тест
Хотя бы один тест без параметризации, например на `'8 (999) 123-45-67'` → `'+79991234567'`.

### 2. `@pytest.mark.parametrize`
Один тест с несколькими вход/выход, минимум 3 набора:
- `'8 (999) 123-45-67'` → `'+79991234567'`
- `'+7 999 123 45 67'` → `'+79991234567'`
- `'9991234567'` → `'+79991234567'`

### 3. Негатив через parametrize или отдельно
`normalize_phone` должна кидать `ValueError` на мусоре. Минимум 2 случая, например:
- `''`
- `'123'` (короткий)

Используй `pytest.raises(ValueError)`.

### 4. Fixture
Сделай fixture (например `valid_phone_raw`), которая отдаёт строку телефона.  
Один тест пусть берёт телефон **из fixture**, а не хардкодом в аргументе теста.

### 5. Mark
Пометь один «главный» тест маркером `@pytest.mark.smoke`.

## Подсказки (что помнить)

- `parametrize` — это «один тест, много данных»
- fixture — «подготовка данных/окружения до теста»
- `with pytest.raises(ValueError):` — ожидаем ошибку

Новые слова в задании:
- **parametrize** — подставить разные аргументы в один тест
- **fixture** — функция с `@pytest.fixture`, pytest сам передаёт её результат в тест по имени аргумента
- **mark** — ярлык на тесте (`smoke`, `regress`…)
