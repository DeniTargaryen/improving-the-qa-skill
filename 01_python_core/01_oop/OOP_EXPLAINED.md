# OOP для AQA — зачем и что делать в 1.1 (простыми словами)

## Зачем тебе это (связь с Gemini и работой)

На собесе уже спросили `__repr__` и устройство клиента.  
**Класс** — это способ сказать: «есть объект со **состоянием** (поля) и **поведением** (методы)».

На работе ты уже этим пользовался, даже если не чувствовал:

| В AQA | OOP-смысл |
|-------|-----------|
| `BaseApi(base_url)` | создали **объект** клиента |
| `self.base_url` | **состояние** объекта |
| `client.get("/posts/1")` | **метод** — действие над этим объектом |
| `Account` в задании | учебный «счёт»: тоже состояние + действия |

`Account` — не банковская система. Это **тренажёр `self`**, как гантели перед жимом. Потом Money (`__repr__`) и наследник BaseApi — уже ближе к собесу.

---

## Три слова

1. **Класс** (`class Account`) — чертёж.  
2. **Объект / экземпляр** — конкретный счёт: `acc = Account("Ann", 100)`.  
3. **`self`** — «этот конкретный объект» внутри методов.

Когда пишешь `acc.deposit(50)`, Python вызывает что-то вроде `Account.deposit(acc, 50)`, и внутри метода `self` — это как раз `acc`.

---

## Что должно уметь Account (по шагам)

### Шаг A — `__init__` (создание)

При `Account("Ann", 100)` нужно **запомнить** на объекте:
- кто владелец → `self.owner`
- сколько денег → `self.balance`

У тебя это уже сделано — **смысл верный**.

### Шаг B — `deposit(amount)` (положить деньги)

Смысл: баланс **увеличить** на `amount`.  
Меняется **`self.balance`**, не отдельное поле «amount как главная касса».

Правило из TASK: если `amount <= 0` → ошибка `ValueError`.

### Шаг C — `withdraw(amount)` (снять)

Смысл: баланс **уменьшить** на `amount`, но **нельзя** уйти ниже нуля.  
Если снять больше, чем есть, или amount <= 0 → `ValueError` (не «обнулить и молча продолжить»).

## Разбор твоего кода (без готового решения)

```python
def deposit(self, amount) -> None:
    self.amount = amount   # ← проблема
```

Ты создаёшь/перезаписываешь поле `amount`, а **`balance` не трогаешь**.  
После `deposit(50)` баланс как был, так и остался.  
Нужно менять **баланс счёта** (`self.balance`), используя переданный `amount` как «сколько добавить».

```python
def withdraw(self, amount) -> None:
    self.amount = amount
    self.balance -= amount
    if self.balance < 0:
        self.balance = 0
```

Идея «вычесть» — ближе. Но:
1. снова лишнее `self.amount`;
2. если ушёл в минус — по TASK нужно **запретить** операцию (`ValueError`), а не занулить баланс после факта;
3. проверять «хватает ли денег» **до** вычитания (или откатывать) — смысл: снятие не должно портить счёт.
